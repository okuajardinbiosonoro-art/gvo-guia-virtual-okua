# Metodología de tickets

GVO avanza por tickets pequeños, cerrables, documentados y probados.

## Reglas

- Un ticket debe tener alcance claro.
- Un ticket no debe mezclar infraestructura, diseño final y contenido real si no fue aprobado.
- Cada ticket debe declarar criterios de aceptación.
- Cada cierre debe indicar pruebas ejecutadas y pruebas no ejecutadas.
- Si cambia arquitectura, flujo, identidad u operación local, se actualiza documentación.
- Si una decisión tiene impacto duradero, se crea o actualiza un ADR.

## Cierre mínimo

Un ticket se considera cerrado cuando el código compila, las pruebas acordadas pasan, la documentación queda alineada y el estado real se reporta sin exagerar validaciones.
